Use this flow before sending reference media to generation or a source video to a video-cleaning job:

1. Call `POST /files` for each file to receive an upload grant and `file_id`.
2. Send the file bytes to `upload_url` with every returned `upload_fields` entry as multipart form data.
3. After the upload succeeds, pass `file_id` in the relevant generation field or as `input.video` for [video cleaning](/guides/video-cleaning).

<Note>
  Receiving a `file_id` does not mean the file has been uploaded. Complete step 2 before submitting generation. Use `file_id` directly; you do not need to construct a storage path or download URL. `upload_fields.key` is also accepted.
</Note>

`POST /files` creates a signed upload grant. Send JSON with the MIME type, file size in bytes, and filename. This endpoint does not receive the file bytes.

```bash
curl https://api.creatok.ai/v1/files \
  -H "Authorization: Bearer $CREATOK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"content_type":"image/jpeg","size":123456,"filename":"reference.jpg"}'
```

All three fields are required. `size` must be a positive integer. `filename` must contain 1–255 characters after trimming and no control characters. Send a MIME type without parameters, such as `image/jpeg`. Unknown fields are rejected.

The HTTP `200` response contains `file_id`, `upload_url`, `upload_fields`, and `expires_at`. Upload with a **multipart POST**, not PUT. Include every returned form field unchanged and append the `file` field last. Do not send your API key to the upload URL.

```javascript Node.js
import { readFile } from "node:fs/promises";

const bytes = await readFile("reference.jpg");
const response = await fetch("https://api.creatok.ai/v1/files", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.CREATOK_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ content_type: "image/jpeg", size: bytes.length, filename: "reference.jpg" }),
});
if (!response.ok) throw new Error(await response.text());
const grant = await response.json();
const form = new FormData();
for (const [key, value] of Object.entries(grant.upload_fields)) form.append(key, value);
form.append("file", new Blob([bytes], { type: "image/jpeg" }), "reference.jpg");
const upload = await fetch(grant.upload_url, { method: "POST", body: form });
if (!upload.ok) throw new Error(await upload.text());
console.log(grant.file_id); // Use in referenceImageKeys or firstFrameKey.
```

The signed grant expires after six hours. Image uploads are limited to 10 MiB; other uploads to 100 MiB. The storage service rejects uploads exceeding the signed limit. Model-specific restrictions can be stricter; see [Video models](/guides/video-models).

Wait for a successful upload before submitting a job. Use the returned `file_id` or `upload_fields.key`; both refer to the same uploaded object and are scoped to your workspace. Video references go in `referenceVideoKeys`; audio references go in `referenceAudioKeys`. For video cleaning, pass the uploaded source video as `input.video`. The cleaner accepts videos up to 50 MiB, even though the file upload grant allows up to 100 MiB for video files. Check [video cleaning](/guides/video-cleaning) for accepted formats and duration.

Uploaded inputs are temporary. Submit promptly, and keep your originals in your own storage. An expired grant requires a new grant and upload. An accepted job retains its own copy of reference inputs.

## Upload reference audio

Follow the same grant and multipart upload steps for audio. For an MP3 file, use `content_type: "audio/mpeg"`, the actual byte size, and its filename in `POST /files`. In the Node.js example above, read your audio file and use the same audio MIME type in the request and the `Blob`.

Audio files must be nonempty, use an `audio/*` content type, and be at most 100 MiB. Complete the upload before passing each returned `file_id` in the `input.referenceAudioKeys` array. Do not pass a public URL. The models enforce stricter per-file limits at submission — at most 15 MiB per audio file, with per-model count and duration limits. Seedance 2, Fast, and Mini also require a reference image or video in the same request. See the [Seedance 2 family reference audio example](/models/video/seedance-2/generation#reference-audio) and the [Seedance 2.5 reference audio example](/models/video/seedance-2.5/generation#reference-audio).
