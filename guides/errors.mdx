---
title: "Errors"
description: "Handle HTTP errors and failed jobs."
---

The API reports problems in two ways:

- **HTTP errors** report request failures. Validation, balance, and admission rejections do not create a charged job. A network failure or server error can leave the outcome unknown: retry the same body and idempotency key instead of creating a new request.
- **Failed jobs** mean a job was created and later failed. The job has `status: "failed"`, and the charge is refunded.

Every response includes an `X-Request-Id` header. Include it when you contact support.

## HTTP errors

```json
{
  "error": {
    "type": "invalid_request",
    "code": "invalid_parameter",
    "message": "input.prompt is required",
    "param": "input.prompt",
    "request_id": "req_..."
  }
}
```

Branch on `code`. The `message` is for humans and can change.

| HTTP | `type` | `code` | What to do |
| --- | --- | --- | --- |
| 400 | `invalid_request` | `invalid_request` | The body is not valid JSON. |
| 400 | `invalid_request` | `invalid_parameter` | Fix the request. `param`, when present, identifies the field. |
| 400 | `invalid_request` | `missing_parameter` | Add the missing field or header named in `param`. |
| 400 | `invalid_request` | `max_cost_exceeded` | The job costs more than `max_cost_usd`. Raise the limit or pick a cheaper input. |
| 400 | `invalid_request` | `media_too_large` | Reduce the upload size. See [Files](/guides/files). |
| 401 | `authentication_error` | `invalid_api_key` | Check that the key is a valid, unrevoked `cok_` key. |
| 402 | `billing_error` | `wallet_not_enabled` | Contact support to enable the API wallet. |
| 402 | `billing_error` | `insufficient_balance` | Top up your API wallet. |
| 404 | `not_found` | `job_not_found` | The job does not exist in this workspace. |
| 409 | `conflict` | `idempotency_key_reused` | Use a new `Idempotency-Key` for a different request. |
| 429 | `rate_limit_error` | `concurrency_limited` | Wait `Retry-After` seconds. See [Concurrency](/guides/concurrency). |
| 500 | `api_error` | `internal_error` | Retry with the same `Idempotency-Key` and body. |
| 503 | `api_error` | `service_unavailable` | Wait `Retry-After` seconds and retry the same key and body. |

## Failed jobs

A failed job has an `error` object with a `code` and `message`:

```json
{
  "id": "job_...",
  "status": "failed",
  "error": {
    "code": "content_rejected",
    "message": "The provider could not accept this generation request."
  }
}
```

| `error.code` | Meaning | What to do |
| --- | --- | --- |
| `model_busy` | The model is at capacity. | Resubmit with a new `Idempotency-Key` after about 30 seconds. |
| `content_rejected` | The input or output did not pass moderation. | Change the prompt. |
| `provider_unavailable` | The generation service was unavailable. | Resubmit with a new `Idempotency-Key`. |
| `processing_failed` | Generation failed. | Resubmit with a new `Idempotency-Key`. |

Failed jobs can be returned directly by `POST /videos/generation` with HTTP `202` when generation is rejected at submission time. Always check `status` on the returned job.

For failed or canceled jobs, inspect `cost.refunded_usd` for the recorded refund; `cost.amount_usd` remains the original charge.
